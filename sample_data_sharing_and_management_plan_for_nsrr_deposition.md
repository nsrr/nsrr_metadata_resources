### 1. Data Type
This project will collect clinical, demographic, survey, and physiological sleep-study data from approximately 2,000 adult participants assessed at four time points over five years. Data modalities will include standardized questionnaires (e.g., sleep habits, lifestyle, and comorbidities), anthropometric and clinical measures, and overnight polysomnography (PSG) recordings. Tabular data (survey, demographic, and clinical variables) will be shared in comma-separated value (CSV) format; raw PSG signals will be provided in European Data Format (EDF/EDF+); and PSG annotations (e.g., sleep staging and respiratory events) will be provided in XML, which is consistent with NSRR recommendations for raw signal and annotation data.
As the designated data repository, the National Sleep Research Resource (NSRR) will conduct data migration, quality control and assurance (QC/QA), metadata extraction and curation, and version control for both data and metadata. Depositing data in these standardized formats will enable variable-level search and exploration, cross-dataset comparisons, as well as cloud-based storage, online computation, analysis via the NSRR Analytical Pipeline (NAP) and Luna pipeline, and other enhanced access capabilities via an NHLBI cloud-based eco-system (i.e., BioDataCatalyst).
Metadata will include a comprehensive data dictionary, study protocol documentation, variable codebook, and README file. Only de-identified data necessary to validate and replicate study findings will be preserved and shared; intermediate processing files and internal logs and information containing PHI will not be distributed.

### 2. Related Tools, Software and Code
Access to the shared data will not require proprietary software: tabular CSV files can be opened in R, Python, or similar; PSG EDF/EDF+ files can be processed by freely available open-source software. Annotation-XML files follow standard schema and can be parsed in standard XML libraries. The NSRR team will also harmonize the polysomnography signal and annotation data using the Luna software package (freely available on github) to make analyses simpler for future reuse.
All analysis code, scripts (R, Python), configuration files, pipeline documentation and relevant software versions will be published alongside the data at NSRR. Active data storage and transfer during collection and processing will use our institution’s HIPAA-compliant server and institutional Dropbox (or equivalent) instance; final archived data and code will be accessible in NSRR.

### 3. Standards
We will adopt community standards to ensure interoperability and future reuse. Raw PSG signal data will be stored in EDF/EDF+ format and annotated using NSRR canonical channel labels and annotation conventions. Derived summary metrics from PSG (e.g., AHI, total sleep time, arousal index) will be provided in CSV files, and key variables will be mapped to NSRR harmonized terms. Questionnaire and clinical data will use instrument items and response formats aligned with the NIH Common Data Elements (CDE) where applicable. Metadata (study‐level and variable‐level) will be tracked via JSON schemas in alignment with NSRR metadata practices, enabling mapping to FAIR principles.

### 4. Data Preservation, Access, and Timelines
Upon completion of data cleaning and internal quality control, the full dataset (tabular, signal, annotation), metadata documentation (protocol, codebook, README, analysis scripts), and code will be deposited to NSRR. Each dataset will receive a persistent digital object identifier (DOI) via DataCite Fabrica (https://doi.datacite.org/). These DOIs point to the dataset landing page and will remain accessible in perpetuity. The DOI is displayed in the footer of the dataset landing page. Data will become publicly available no later than the time of the first peer‐reviewed publication using the dataset or the end of the performance period, whichever comes first. Once the data are submitted to NSRR, NSRR will control the long-term persistence of the data set.  Currently, NSRR has no process for deleting or retiring data sets, and has created a stable and sustainable infrastructure that will allow currently hosted data to stay available through the lifetime of the repository. NSRR will facilitate the data ingestion and integration into the NHLBI Bio DataCatalyst could-based eco-system.

### 5. Access, Distribution, or Reuse Considerations
All data will be de-identified prior to deposit; we will review participant informed consent to ensure broad data reuse is permissible. The NSRR team will review and identify any restrictions (e.g., no commercial use, geographic limitations), and undertake additional processing on all raw data and datasets upon receipt to confirm that all identifiers have been removed prior to making a dataset available to NSRR users. Access to the data via NSRR will require completion of the NSRR Data Access and Use Agreement (DAUA), which prohibits re-identification and restricts redistribution. The NSRR Data Access Committee will evaluate requests; time-limited access renewals may apply and commercial reuse will follow consent terms. Any limitations based on consent or institutional agreements will be indicated in the dataset metadata. Data sharing via NSRR will also be compliant with any existing federal or internal regulations on data sharing restrictions.

### 6. Oversight of Data Management and Sharing
The study’s Principal Investigator (PI) and designated Data Manager will oversee all aspects of data management, curation, and sharing. The Data Manager will coordinate quarterly team meetings to review compliance with this DMSP (including data ingestion schedule, metadata completion, repository submission) and will maintain documentation, including plans to submit and share data with NSRR. The study PI will review DMSP compliance at the quarterly All-Team meetings and will report any deviations or updates in the annual progress report to NIH.
